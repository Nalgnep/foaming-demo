# 冰箱箱体发泡缺陷根因推理 Demo

给工艺、质量、设备工程师看的静态页：把空洞的长相和现场证据交给页面，它按本体模型 v1.0 的 20 条种子规则列出嫌疑、写出每一分的理由，并推荐下一步先查什么。行业知识包 v1.1、国标锚点和海信现场看板都在页内，只作对照和核查提示，不参与打分。

打开 `index.html` 就能用。推理在浏览器里完成，照片和证据不离开这台电脑。

## 部署

GitHub Pages：Settings → Pages → 分支选发布分支、目录选根目录（`/ (root)`）。入口就是根目录的 `index.html`，不需要构建。

仓库里放了 `.nojekyll`，避免 Pages 的 Jekyll 处理把页面改写。不请求外部字体，中文走系统字体（苹方、微软雅黑、思源黑体），国内网络下也能打开。

本地查看：

```bash
python3 -m http.server 8765
```

然后打开 `http://127.0.0.1:8765/`。

## 页面怎么用

1. 用结构化表型、文字描述，或六种剖切形态，把缺陷长相定下来。证据知道多少填多少，不知道留「无数据」。
2. 杯泡分流是第一刀：异常查料、配比、混合、料温；正常查模具、排气、注料。
3. 点「开始推理」。复核时可勾选「跳过逐步动画」。
4. 先看定案置信，再看口头结论、单因素翻转、因果图和评分明细。百分比是得分份额，不是校准后的概率。
5. 「下一步先查什么」优先杯泡，其次是还能把前两名拉开、且还没填的证据。标了「待验证」的问法不加减分。

工艺窗口里的料温、模温、混合压力，填了实测值可以一键写入对应证据。模温偏高不写入种子分：种子规则只覆盖模温偏低，偏高在海信看板里更多对应脱粘或漏料。

## 种子分（这轮没有改权重）

```
种子分 = round(历史占比 × 100 × 邻近表型折扣) + 支持证据权重 − 25 × 普通排除
强排除命中则归零，结果截断到 0–100。
邻近表型候选的起步分打六折。杯泡正常或异常时，对应一侧 +10。
```

三条内置案例在杯泡「未做」时的领先项应保持为：

| 案例 | 领先规则 | 种子分 | 第二名 |
| --- | --- | --- | --- |
| 排气孔堵塞 | R-V01 排气孔堵塞 | 95 | R-V06 密封失效漏料，19 分 |
| 计量漂移充填不足 | R-V04 注料量不足 | 75 | R-V01，21 分 |
| 模温过低弥散空洞 | R-V07 模温过低前锋凝胶 | 70 | R-V01，21 分 |

定案置信单独计算，不改上面的分数。杯泡还没做时，最高只到「中」。要到「高」，需要领先超过 40 分、至少 3 条支持证据、杯泡已经做，并且领先项不是邻近表型打折来的。

阈值和先验是示例。正式上线前要用本厂工艺规程和 50–100 个历史闭环案例回测，不能把这页的分数当成判责。

## 边界

- 给的是带证据的嫌疑排序，最终根因以现场核查和专家确认为准。
- 得分份额是正分归一化，不是贝叶斯后验。没有标注案例之前，不在演示里编似然。
- 查不到可靠出处的数字不入库，见页末「知识空白」。
- 海信看板和知识包 v1.1 里标成待验证的条目，不能写成规则。
- 上传照片只在本机预览。没有视觉模型，页面不会把每张图都判成同一种空洞。
